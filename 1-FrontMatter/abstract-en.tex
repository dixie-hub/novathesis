One of the main threats to anonymity systems such as Tor is the so-called Sybil attack, in which an attacker impersonates multiple identities for a single entity. To address this threat, I propose Dittor, an anonymous and Sybil-resistant credential scheme.

Dittor relies on credentials approved by external entities to anonymously validate the unique identity of a Tor network node operator. This credential system does not allow more than one identity per node operator, thus mitigating possible Sybil attacks. While previous attempts sought to identify Sybil nodes in the Tor network for mitigation, Dittor solves the problem at its root by associating anonymous credentials, which validate the subject's identity, with a pseudonym, which is then used as an identifier in the Tor network to group an entity's nodes under a single link, without revealing its identity. To achieve this, mechanisms such as Sybil-resilient Anonymous Signatures and Zero-Knowledge Proofs are used to build a Self-Sovereign Identity system, culminating in a Sybil-resilient Anonymous Signatures with Stateless Issuing scheme, to which Dittor adds a discrete logarithm equality proof that cryptographically links the issued credential to the presented pseudonym, preventing a user from bypassing the uniqueness check with a freely chosen secret. The scheme was implemented in Java and integrated into the Tor codebase in C, through a bridge that validates the proof directly in the node descriptor publication flow.

The solution was validated through tests in a Tor network simulation environment based on Chutney, confirming the detection of invalid proofs, the rejection of reused identities without a shared family, the legitimate acceptance of multiple nodes belonging to the same entity, and safe behavior in the event of validation backend failures. The performance results obtained show a negligible cost introduced by Dittor relative to the Tor network's reference metrics, confined to the node descriptor publication process and never to the end user's data path.

Validating issuing entities' verification of possession of a unique real-world attribute is left as future work, currently assumed to be resolved by an entity external to the cryptographic scope of the scheme.
